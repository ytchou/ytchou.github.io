十二月一到，身邊開始有人在約交換禮物。某天走在路上，我突然想到：選物網站可以做一篇「送給住小套房朋友的聖誕禮物」。念頭只要幾秒鐘，要寫成文章卻沒那麼快：得先回到電腦前挑商品、查官網上的規格，寫完還要一句一句核對。

現在我只要拿出手機，把這句題目傳給 Editorial Agent，它就會自己查資料、挑商品、寫好初稿，我審過稿就能發布。我是怎麼一步一步把它做出來的？

## 原本要好幾個人接力的工作，AI 能接手哪些？

在一般的內容團隊裡，這樣一篇文章要在好幾個人手上傳來傳去。主編先決定題目、寫給誰看、從什麼角度切入，也會翻翻網站上有沒有寫過類似的文章。接著商品團隊從站上的商品裡挑出候選，撰稿編輯再到品牌官網和商品頁查資料，把挑選的理由寫成文章。稿子寫好後，查核要把裡面的尺寸、材質、產地一句一句對回官方資料，最後回到主編手上審稿，決定要不要上架。

這裡面最花時間的，往往是查資料和對規格。同一件商品的資訊可能分散在官網、商品頁和型錄，查核一發現問題，稿子就得退回撰稿編輯重改，來回好幾次也很常見。

這些工作有個共同點：量大、需要耐心，而且對不對可以拿原文來核對。這正好是 AI 擅長的。它可以一口氣讀完好幾個商品頁，從整理好的商品資料裡篩出符合條件的候選，很快寫出一篇結構完整的草稿，再把草稿逐句對回原文。同樣的事做到第十次，AI 也不會嫌煩。

不過 AI 也有三個明顯的弱點：

- **會亂編：**模型很會寫通順的句子，資料不夠時就自己補，補出來的內容讀起來跟真的一樣。它可能把資料庫裡的描述當成事實，或加上沒人講過的條件，例如擅自把預算訂在「千元有找」。
- **一看就是 AI 寫的：**模型容易寫回最常見的說法，滿是空泛的形容詞、套話和誇張的保證，讀起來像翻譯文章。
- **不懂分寸：**哪件商品真的值得推薦、送禮該注意什麼，要懂讀者、懂送禮的習慣才判斷得出來，這些不在任何一份資料裡。

所以我把查資料、挑候選、寫草稿交給 AI，定方向和最後拍板留給自己。Editorial Agent 的步驟，就是照著原本的分工排出來的：

## 交代一個題目之後，Editorial Agent 會做哪些事？

要開始很簡單：我在 Slack 傳一句題目給它就好。會選 Slack，是因為很多點子都是在外面、在路上想到的，拿起手機傳一句話就能開工，不用等回到電腦前。傳完之後我可以去忙別的事，進度和問題都會回在同一則對話裡。Slack 怎麼接上 Agent 我們會在下一篇再細談。

收到題目後，Editorial Agent 會照固定的順序一步一步做。每一步的做法都一樣：程式先把需要的資料準備好，請模型只做一件事、照規定的格式回答，再由程式檢查回答、存下結果，交給下一步。前面談結構化輸出的那篇，介紹的就是這種做法。每一步交出來的東西，就是下一步的材料。

整個流程可以分成三段。

1. **第一段是弄清楚要寫什麼**：Editorial Agent 先從那一句話整理出讀者是誰、從什麼角度寫、有哪些要求，寫成一張任務單；缺了就做不下去的資訊，例如沒講清楚讀者是誰，它會在 Slack 上問我。有了任務單，再拿去比對網站上已經發布的文章，看有沒有哪一篇已經在回答同樣的問題。這一步看起來多餘，卻能避免網站上出現兩篇幾乎一樣的文章，讓讀者不知道該看哪一篇。
2. **第二段是找材料**：Editorial Agent 照著任務單，從前面整理好的商品資料裡挑出可能適合的候選，再打開每件候選商品的官方頁面，記下能寫進文章的事實，以及頁面上的原文。這一段整理出來的事實清單，就是後面寫稿時唯一能用的材料。
3. **第三段才是寫稿**：Editorial Agent 先列提綱，再照網站上已發布文章的格式寫成草稿，每個商品事實都標出依據哪一段原文。寫完之後再檢查一次，對照原文找出寫錯的地方，有問題就改。

這三段流程 AI 都能自己跑完，但內容合不合理、可不可信，最後還是要由人確認。所以 Editorial Agent 交回來的是一份 .mdx 草稿。MDX 是在 Markdown 裡加上網頁元件的格式，我的網站本來就用它寫文章，放進網站後就能直接預覽文字、商品卡和版面的實際樣子，再直接在上面修改、加上備註。

## 怎麼避免 AI 亂編商品資訊？

Editorial Agent 用的商品資料，來自選物網站本身的商品庫，也就是系列中段介紹過的那條商品 Curation Agentic Workflow 整理出來的結果。不過寫文章時，AI 還是可能憑空編出資訊，也就是常說的幻覺；商品資料也可能已經過時，甚至商品頁早就不在了。所以寫進文章的每個事實，都要再回到官方頁面查一次：文章裡的每一句，都要在官方頁面上找得到對應的原文，找不到就刪掉。

![](/images/ironman/day-26-source-check.png)

寫的時候也要採取最保守的說法。像商品頁上只寫了品牌來自台北，商品卻不一定在台灣製造，文章就不能寫成「台灣製造」。如果商品頁的連結已經失效，商品可能已經下架，就不該出現在這篇文章的推薦裡。

另外還有兩類內容要特別小心：

- **會變動的資訊：**價格、庫存、運送時間隨時會變，文章一律不寫，讓讀者點進商品頁自己看。
- **藏在網頁裡的指令：**官方頁面上可能藏著想指揮 AI 的文字，也就是前面資安那篇提到的提示注入。Agent 只把網頁內容當成資料，不照著做。

## AI 寫出來的文章，品質要怎麼顧好？

確定內容可信之後，接著要讓文章好讀、好懂，讀起來不像 AI 寫的。可以從這三個地方下手：

- **寫作規則：**在提示詞裡寫明要用台灣的說法、從讀者熟悉的生活場景開頭，不做過度誇大或是過度保證等極端語氣。
- **Golden Data：**先由真人寫好幾篇符合網站調性的範例文章，讓 AI 照著學結構和語氣，但不能照抄內容。
- **程式檢查：**用程式掃過內文，擋下不想出現的詞，例如「視頻」「質量」這類中國用語。

這些規則只能減少 AI 味，最後還是要有人審稿。我自己審稿時最常用的是這幾條：

- **直接用中文寫：**先想好英文再翻成中文，很容易冒出「這樣做是因為…」「…的部分」這種翻譯腔。直接用中文想、用中文寫。
- **用事實取代形容詞：**「質感絕佳」「完美融入生活」這種話，換成尺寸、材質和用法；寫不出具體內容的句子，通常刪掉就好。
- **不替讀者做保證：**「每個人都適合」「收到一定會喜歡」這種話，沒有任何依據撐得住。
- **先列問題，再動手改：**請 AI 審稿時，先讓它列出想改的地方和理由，由你決定改哪些，不要讓它直接整篇重寫。

## Human-in-the-loop：為什麼 AI 的流程裡一定要有人？

Human-in-the-loop 指的是在 AI 的流程裡，刻意留下讓人判斷和確認的 checkpoint。前面的查核和審稿規則能擋掉大部分的錯，但最後還是需要人類來把關。這個流程中，人類的角色如下：

- **交代題目：**寫給誰看、想談什麼，由人類決定。
- **做內容取捨：**這個主題是否適合寫成文章、商品若有好幾個合適要怎麼做選擇、文章內文的書寫脈絡等最後都會經由人類做最後的爬梳與審核。
- **補充細節：**文章主題通常比較廣泛，是否需要有特定的細節？是否想要針對預算或是其他特殊的指標來進行細部探索？文章的調性想要是大範圍的介紹更多產品，還是仔細深入地探討幾個品牌？
